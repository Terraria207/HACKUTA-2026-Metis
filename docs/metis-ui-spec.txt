Metis — UI Spec
Nov 15, 2026  ·  @Elliot
Overview
Metis's interface runs from a pixel-art title screen, through New Journey or Load Journey,
to a top-down sea map where each basis group is an island. This spec restructures the
original UI notes and fills gaps from the design doc, Metis — Lower-Level Overview; items
marked Added are suggestions found in neither.
Both menus end in the same scroll transition, and only a review document opens without
going to the map first. On the map, the paper input, Odyssey discussion and route finder
sit around the sea, and a toggle switches to the simplified view.
Terms: a basis group is what the design doc calls an island module: a field of mathematics
(e.g., linear algebra) built once by the gods and shared by every journey.
Title screen
The title screen offers two choices, New Journey and Load Journey, each on a rolled scroll
in front of a pixel-art beach.

Menu scrolls
Added: keyboard and touch. Arrow keys move between scrolls, Enter unrolls or
selects, Esc rolls back up. On touch screens, which have no hover, a tap unrolls the
scroll.
New Journey
New Journey creates a journey: a name, the basis groups to explore, the models and their
API keys, and the run settings from the design doc. Added: clicking the New Journey
scroll enlarges it into this setup form.
Basis groups
Pick one or more basis groups (islands) from the database, e.g., linear algebra, graph
theory, probability.
Each basis group is built once by a powerful model (the gods, Claude Fable 5.2) and
saved. If an earlier journey already built it, it is linked at once, read-only.
The picker marks each group as Ready (saved) or Needs building, so the user knows
before starting whether a build is coming.

Choosing a journey
Added: a review document opens on the same full-screen scroll as the transition, with

Transition
Once the final choice is made in either menu, the scroll flies to fill the screen and fades
into the top-down ocean.
1. The user confirms: Set sail (New Journey) or Open journey (Load Journey).
2. The scroll flies toward the viewer and grows until it covers the whole screen.
3. It fades into the top-down ocean view of the journey's islands.
Added: if any basis group still has to be built, the scroll holds at full screen and shows
the build's progress (for example, the island being inked onto the parchment) until
the journey is ready. The design doc calls for a progress indicator here.
Added: keep the animation short and let a click or Esc skip it, since returning users will
see it every time.

A hyperedge (several premises that together give one conclusion) shows walkers
from each premise meeting at a campfire, then one walking on to the conclusion. This
mirrors the design doc's junction dot.
Status on the map (from the design doc)
Nodes and edges new in the latest run are highlighted.
Unintegrated concepts are outlined. Proposed nodes are quarantined, so they look
faded until accepted.
Zoom and pan
Zoom in and out with the scroll wheel, a trackpad pinch or + and − buttons; drag to
pan; a Fit all button shows every island again.
Added: zoom in whole steps (1×, 2×, 3×…) so the pixel art stays sharp.
Added: more detail appears as the user zooms in. Zoomed out shows islands, grass
patches and boats; zoomed in adds paper characters and walkers.
Zooming also means the map no longer has to fit on one screen, so islands keep their
spacing on smaller windows.
Added: a small minimap in a corner while zoomed in.
Pointing at a patch, character, walker or boat shows its name; clicking opens its details
(see Other UI elements).
Simplified view
A toggle swaps the scenery for the bare node system: nodes as dots, edges as lines and
groups as highlighted, labeled regions.
Toggled by a button on the map and a keyboard shortcut (G).
Unlike the sea map, this view draws every node, basis nodes included.
Added: the camera carries over, so zoom, pan and the current selection stay put when
switching views.
Styling (from the design doc)
Nodes colored by status: Established, Proposed, Accepted, Proven. Unintegrated
concepts outlined.
Edges styled by tier: solid for verified, dashed for cited, dotted for intuitive.
Hyperedges drawn as lines converging on a junction dot before the conclusion.
Nodes and edges new in the latest run highlighted.

Filters and search (from the design doc; they apply in both views)
Filter by tier, existing tag (Existing, Not found, Unchecked), island, run, or new
connections only.
Search concepts by name or by meaning (vector search).
Paper input
A panel on the map takes a research paper, by attaching it or typing it in, and starts a run
on it.
Attach a PDF, or type or paste an arXiv ID or URL. From the design doc: or pick a paper
already in the journey's corpus.
Before the run starts, the panel shows where the paper sits in the tree (its MSC
codes, which the decomposer assigns if the paper has none) and lets the user correct
it.
From the design doc: add papers without running them, in bulk by arXiv IDs or MSC
category, so the crew has papers to draw as targets.
Run controls: Start, Pause, Resume and Cancel, available throughout the run.
As the run finishes, new paper characters appear on their islands and new boats set
sail, highlighted as new.
Added: the panel is styled as a message in a bottle washed up at the map's edge.
Odyssey discussion
While a run is going, a narrator model, Claude Haiku 5.5, turns each agent's output into
dialogue between the Odyssey characters, shown as pop-ups with the speaker's portrait.
Why Claude Haiku 5.5: it runs on every trace entry, so it has to be fast and cheap; it
reliably follows a rule like "keep these facts word for word"; and it reuses the Anthropic
key the journey already needs for the gods, Eurylochus and Odysseus. It can be swapped
in the models table like any other role.
Pop-ups
Each pop-up shows the speaker's pixel portrait, name and line, in the order the agents
produced them.
Lines advance on their own, with a speed control; a click advances, and the discussion
can be skipped or muted.

Who speaks for each step
Keeping it accurate (Added)
The narrator restyles wording only. Verdicts, tiers, existing tags, concept names and
citations are passed through unchanged.
Each pop-up links to the trace entry it came from.
From the design doc, the raw live trace stays one click away: grouped by pipeline step,
filterable by agent, crew mate or step, and expandable to full text and evidence. Like
the trace, the discussion shows only what agents write, not hidden model reasoning.
When many entries arrive at once (four crew mates proposing together), the narrator
folds them into one short exchange so pop-ups stay readable.
Route finder
The route finder connects any two nodes, draws the route on the map, and writes it out
formally as a chain of logical steps.
Picking the ends
Choose the start and end nodes by clicking them on the map or searching by name or

Route types (Added, following the design doc's rules for proofs)
On the map
The route is highlighted: walkers along each edge on an island, a boat for each
crossing between islands.
Added: a Play button sends a small ship or walker along the route, with the camera
following.
Formal view
A numbered list of steps. Each step gives its premises, its conclusion, the edge type
(implies, generalizes, …), its tier and its evidence or source.
A hyperedge needs all of its premises reached, so a route through one is shown as a
tree of steps rather than a single chain, as in the design doc's proofs.
A summary line gives the route's length and overall tier, the lowest tier of any step.
If no route exists under the chosen type, the finder says so.
Added: the formal view can be copied or exported as text.
